#### 🚀 What I'm building

- **[ai-oncall](https://github.com/kalyvask/ai-oncall)**: LLM agent that diagnoses production incidents in under 30 seconds and hands the oncall engineer something verifiable to act on. The service graph is built from observed OTel spans (Prometheus and Loki for live telemetry) rather than a static topology config, so the agent can rule out services that physically can't have caused this incident before burning any of its 8 tool calls on them. Every claim cites the tool call or deploy diff it came from, so a diagnosis can be checked rather than trusted on faith. Remediations are staged into recommend, propose, and auto tiers behind an action allowlist with a dry-run preview and one-click Slack rollback, so autonomy is granted per-action, not per-incident, and a bad call can be reversed in seconds. Deterministic abstention rules (cold start, low confidence, budget exhausted, conflicting leads) override the model when the evidence is thin, so it abstains rather than fabricate a fix. A replay command re-runs the pipeline on stored incidents and a CI-fail-on-drift eval harness catches silent regressions when prompts or models change, scored against a starter benchmark of real public-postmortem incidents. Production plumbing wired through: durable job queue with retries, HMAC-signed webhooks, per-tenant auth, PII/secret redaction, latency and cost SLO budgets. Multi-tenant, schema-validated. *Python · FastAPI · Next.js · Anthropic API*
- **[chief-of-staff](https://github.com/kalyvask/chief-of-staff)**: Personal chief-of-staff agent that drafts emails, preps meetings, shapes next week's calendar, and routes decisions into the right project log, so I stop being the manual router on every loop. Reads `context/`, `memory/`, and per-project state in `projects/<slug>/` before responding, so it starts with the situational awareness I would have rather than asking me for it. A JSONL work queue tracks every in-flight item with provenance and audit trail, so nothing falls through the cracks and every action is traceable back to who or what asked for it. A tier-based permission engine gates every side-effect action before it runs and logs every permit decision; each slash command declares a tier ceiling so a read-only command can't accidentally promote into sending an email or moving a meeting. Inbound channels for forwarded emails (subject conventions parse project tag and priority) and Slack thread mentions with in-thread `/approve` and `/close` close the loop from wherever I'm reading. Conformance rules in JSON config audit every draft (em dashes, AI tells, flattery, missing sources footer, bullet salad), so drafts stay in my voice instead of drifting into ChatGPT-default. Local web UI renders the queue (with undo and history), active projects, and a voice-audit pass-rate panel, with the same surfaces exposed over REST, so I can see what's running and roll back if I don't like it. Six-question first-run wizard writes the initial context files so it works on day one; an eval harness (`npm test`, 39 fixtures) catches substrate regressions in CI. Borrows patterns from Karpathy's LLM-OS framing (persistent memory, agent reads the world before acting) and Garry Tan's [gbrain](https://github.com/garrytan/gbrain) (typed-link entity graph, audit trail on every action). *Node.js · Claude Agent SDK · MCP · Gmail · Google Calendar · Slack*
- **[inside-the-agent](https://github.com/kalyvask/inside-the-agent)**: Reads the SAE features firing inside an LLM agent at each decision step and intervenes at the residual stream while the agent is still acting, so specific failure modes (falling for promotional banners, clicking invented buttons, wandering off-task) can be studied and steered rather than observed in the logs after the fact. Demonstrated on a browser shopping agent that fails every baseline trial: two targeted SAE feature edits at the first decision step lift success from 0% to 83.3% (+83 pts, Wilson 95% CIs over 24 trials per policy). Sign-flipped and random-magnitude controls rule out "any intervention works": sign-flipped falls back inside baseline's CI, and the +37 pt targeted-vs-random gap is the actual causal claim about which features matter, not the 83 pt headline. Features are named by ID rather than by semantic label until independently validated, so the project doesn't over-claim what each one represents. End-to-end: a Next.js HUD shows live feature activations and an intervention timeline so a human can see what the agent is keying on as it decides; a Python worker drives the agent through ShopGym deterministic storefronts on Playwright with per-task verifiers, so trial counts and success rates mean what they say; a Modal-hosted brain-server serves Llama 3.1-8B-Instruct with Goodfire SAE on layer 19. Built for Stanford CS153. *Python · Next.js · Playwright · Modal · Llama 3.1 · Goodfire SAE*
- **[winning-writing](https://github.com/kalyvask/winning-writing)**: Agentic writing coach that catches the AI tells, em-dashes, jargon, flattery, and warmth-and-competence misses that make outreach and pitch artifacts sound off, before they go out. Rules are grounded in Stanford GSB's *Winning Writing* (Glenn Kramon) and Rachel Konrad's cold-outreach lectures rather than vibes: 31 Claude skills plus a rule library covering recipient research, surgical edits (em-dash, jargon, adverbs, humanize, warmth-and-competence), pitch artifacts, and voice maintenance learned from sent mail. Browser Coach offers three pipeline modes (single-shot, planner-routed polish, full per-step pipeline) so depth can be traded for speed depending on the stakes, and a span-level inline critic (hover for the rule, Accept/Reject inline) so edits can be evaluated and applied without leaving the draft. Chrome MV3 extension runs the same critic in the Gmail side panel with one-click compose import, opt-in Send-button interception against a cross-model gate (a second Opus call independently approves every send), and live rule sync from raw.githubusercontent.com so rules can be updated without reinstalling. Every annotation cites the points/ or skills/ file the rule came from, so a flag can be argued with on the rule rather than on the assistant. Node eval harness with a golden corpus catches regressions when rules change. *JavaScript; Chrome MV3; Anthropic SDK (prompt caching, web_search, multi-model gating); Claude Skills*

#### 🔬 Research & writing

- **[Enterprise AI Observability](https://alexkalyvas.substack.com/p/trends-challenges-and-opportunities)** *(Stanford GSB · IR 390 · Dec 2025)*. Primary research from 100+ AI engineers and founders. Headline: 60% of AI-natives already run agents in production; the next bottlenecks are **privacy/security, observability, and continual learning**, not hallucinations. Most teams ship without trace coverage and learn their failure modes from customer complaints. Eval-driven development is becoming the new TDD: the teams shipping fastest are the ones who wrote their evals before their agents. Three-part Substack series, generated intros to AI SRE companies and AI experts.
- **[Enterprise AI Time-to-Value](https://alexkalyvas.substack.com/p/how-long-does-enterprise-ai-take)** *(Stanford GSB · IR 390 · Mar 2026)*. Only **14% of practitioners reach measurable impact in under a month**, yet 50% expect that to be standard by 2027 (a 4× expectation gap). The teams hitting fast TTV share three habits: forward-deployed engineering (PMs and engineers in the customer's loop, not behind a CSM), trust transfer (the implementer's reputation matters more than the model's), and measurement discipline (a baseline metric agreed on before kickoff, not after). Argues implementation quality, not model quality, is the next moat.
- **[Rosetta Sycophant](https://rosettasyncophant.streamlit.app)** *(Stanford GSB · AI and Power · Winter 2026)*. AI Interpretability. With Barry Thrasher and Humzah Khan. Live tool detecting identity-based bias in AI translation. Same source text, two user profiles → "invasion" vs "intrusion." Demoed on January 6th reporting from Russian-language sources. Finding: frontier models change word choice based on inferred user politics even when the user metadata is irrelevant to the translation task, which makes "neutral translation" a harder claim than vendors imply.
- **Haptica: Tactile Intelligence for Manufacturing** *(Stanford GSB · MKTG 321 · Mar 2026)*. AI Robotics. With Devanshi Mehta, Grace Stayner, Paola Peraza Calderon, and Facundo Tosi. Wearable tactile-sensor ML for assembly-line connector seating. Trained per-connector classifiers (Random Forest / Gradient Boosting / SVM) on 16 hand-crafted pressure features; F1 0.67–0.83. Hand-crafted features beat a CNN baseline on the small dataset, reinforcing that sparse-data physical-sensor problems still favor classical ML over deep learning. Non-electromechanical assembly failures drive **$14B/yr in U.S. recall costs**, and catching 10% of escapes at a single OEM avoids $50M+ annually.
- **Strike GTM Repositioning** *(Stanford GSB · GTM · Dec 2025)*. AI Cybersecurity. With Sachin Khurana and Christian Gallo. Series-A AI pentesting platform (~$3M ARR), 8 proprietary interviews including XBow and Horizon3. Core finding: buyers won't accept fully-autonomous pentest output as compliance evidence, which makes **hybrid AI + human** structurally more defensible than autonomy claims. Recommends per-asset PTaaS pricing (unlocks 5–10× larger contracts than per-hour), LATAM financial services focus (underserved, regulatory tailwind), and hybrid positioning against fully-autonomous entrants.
- **Knowledge Gardener: A Product Pitch for Glean** *(Stanford GSB · PM · Spring 2026)*. Enterprise AI Applications. With Yedu Pushpendran, Viraj Singh, and Shivani Bajaj. Continuous agent that finds stale and contradicted docs in Glean's Enterprise Graph and routes fixes to the right steward. Thesis: as MCP commoditizes connectors, the retrieval signal (what decays, who owns it, what's asked) is the one asset MCP can't standardize, so Glean's defensibility shifts from integration breadth to retrieval-signal depth. Packaged as a free Health Score plus a paid "Cultivate" tier with tiered autonomy.

#### 🧰 Tools and learning resources

- **[fde-simulation](https://github.com/kalyvask/fde-simulation)**: Hands-on simulations of the Forward Deployed Engineer role on synthetic case studies, so someone preparing for FDE work can practice the actual job (read the customer email, scope the engagement, build and ship a working agent) instead of just reading about it. Two fictional 4-week engagements (Calder Insurance FNOL automation, Helix Capital equity-research earnings notes) with synthetic data and reference solutions per phase, so the shape and difficulty match a real engagement without exposing any client. Working Python agent prototypes ship at the pass^k=5 production threshold (5 agents for Calder, 7 for Helix), so the reference solutions actually run end-to-end and can be forked rather than only studied. Hybrid deterministic + LLM architecture with examiner-readable audit traces, so a reviewer can see why each step took the action it did. 11 portable FDE frameworks (4-source convergence, 3-lens scaffold, Outcome Risk Matrix, workflow decomposition, agent shapes catalog, model-vs-application-layer, 4-dimensional testing, behavioral story types, ownership language, company calibration, consulting/strategy frameworks), so the way of thinking transfers from the simulation to a real engagement. 15 Claude-roleplay stakeholder interview prompts (CCO, lead user, compliance officer, silent skeptic) for interactive discovery; consulting-style case-brief HTMLs that open with the customer email and the engagement clock running; per-phase Claude-graded scoring; a case-aware 3-lens whiteboard tool with deep-link to either case; engagement retrospective and portfolio-piece templates; a senior-candidate skip-ahead path. Doubles as comprehensive interview prep for FDE-style roles. *Markdown · Python · single-file HTML · Anthropic / OpenAI SDK · MIT*
- **[deployment-monitor](https://github.com/kalyvask/deployment-monitor)**: Tracks AI deployment trends across Reddit, Hacker News, and 40+ RSS sources. Claude summarizes and categorizes; Streamlit dashboard surfaces what's actually shipping. LLM consolidates and sends you via email most relevant news for you weekly. Plus an agent layer (`python main.py agent`) that gives the reports memory across runs: a ledger of evolving narratives and tracked-lead validation for opportunity signals. *Python · Streamlit · Anthropic API · SQLite*
- **[role-radar](https://github.com/kalyvask/role-radar)**: PM job matcher for AI companies (you can adjust this based on your target career/roles). Pulls live roles from ~120 AI companies and VC-backed startups via Greenhouse / Lever / Ashby / SmartRecruiters / Workday, scores each 0–100 against your CV, serves a Flask UI that learns from like/dislike feedback. Two one-click LLM workflows per job, both Claude Opus 4.7: an interview prep generator that maps your stories to the role and runs a second-pass critic scoring 1–10 with severity-tagged findings; and a company review using the `web_search` tool (15–25 queries) that emits an investor-grade analysis with valuation timeline, ARR growth, competitor quadrant, funding-rounds table, press / Glassdoor / Reddit sentiment, and a verdict (Strong apply / Apply with caveats / Pass / Inconclusive), every numeric claim cited inline. Plus a stateful agent layer (`role-radar agent`) that tracks pipeline state across runs and drafts cold outreach per job. *Python · Flask · Typer · Anthropic SDK · Mermaid · python-docx · SQLite*
